# 実装の構造

Patchlight は、ブラウザ上で「入力 → 条件や処理 → 出力」を試す独自のイベントシミュレーターです。機器のファームウェア、公式アプリの実行系、公式レシピ形式を再現するものではありません。通信仕様の調査範囲は [PUBLIC-SPEC.md](PUBLIC-SPEC.md) を参照してください。

## 境界

```text
画面の操作 ── trigger(nodeId, value) ──┐
                                     ▼
                              src/core.js
                         検証済みグラフとイベント列
                                     │
                              onEvent(event)
                                     ▼
                          DOM / 描画 / Web Audio
```

`src/core.js` は DOM、音声、ストレージ、ネットワークに依存しません。ブラウザでは `PatchlightCore`、Node.js では `require('./src/core.js')` から利用します。外部パッケージとビルド処理は不要です。

画面の編集状態と出力の見た目は UI が管理します。エンジンが保持する実行状態は、各カウンターの回数、待機中の遅延、処理キューです。

明るさスライダーの変更は仮想入力であり、配線・処理の編集とは区別します。最後の値を保存して `trigger` へ送り、待ち時間・カウント・点灯を引き継ぎます。

UI は通常の編集・設定変更・移動で、描いた色を残します。色を変えて入力を繰り返すと、一枚の絵に重ねられます。作例への切り替え、作品の読み込み、取り消し、最初からのやり直しでは絵も消去します。「出力をリセット」の操作は光・音・絵とエンジンの実行状態をまとめてリセットします。絵はレシピ JSON に含まれず、ページを読み直して復元されるのはブロックと接続です。

## 作品形式

作品は `version: 1` の JSON です。位置は描画用であり、実行順を決めません。

```js
const C = PatchlightCore;
let graph = {
  version: 1,
  title: 'ボタンで光る',
  nodes: [
    C.createNode('button', 'button-1', 100, 100),
    C.createNode('light', 'light-1', 500, 100)
  ],
  edges: []
};
graph = C.connect(graph, 'button-1', 'light-1');

const engine = C.createEngine(graph, {
  onEvent(event) {
    if (event.kind === 'output') console.log(event.type, event.config);
  }
});
engine.trigger('button-1'); // value を省略すると true
```

`validateGraph`、`connect`、`parse` は検証済みの新しいオブジェクトを返します。入力されたオブジェクトを変更しません。`serialize` も検証してから JSON に変換します。

## ブロックの意味

| 種類 | 振る舞い |
| --- | --- |
| `button` / `motion` / `move` | UI が送ったイベントをそのまま渡す仮想入力。実センサー値の取得はしない |
| `brightness` | UI が送った数値を渡す。設定の `value` は 0〜100 の初期表示値で、照度の物理単位ではない |
| `threshold` | 数値が `value` **未満**（`below`）または **超過**（`above`）なら通す。等値と数値以外は通さない |
| `delay` | 入力イベントごとに `ms` 待って同じ値を渡す。まとめたり間引いたりしない |
| `counter` | そのブロックへの到着を数え、`every` 回ごとに、その回の入力値を渡す |
| `light` / `sound` / `paint` | 到着ごとに設定付きの `output` を通知する。発光、音の再生、描画は UI の責任 |

しきい値は毎回の値を比較します。「明るい状態から暗い状態へ変わった瞬間」だけを検出する状態遷移ではありません。入力が合流すると、それぞれ別のイベントとして処理します。合流点で全入力を待つ処理はありません。出力ブロックは `false` や `0` も到着イベントとして扱い、機器のオン・オフ命令には解釈しません。

## 実行順と停止

- キューは FIFO（先に入ったものから処理）。分岐は `edges` 配列の順序で追加します。
- 到着時に `node`、接続を通る時に `edge`、出力時に `output` を通知します。遅延ブロックの `node` 通知は入力到着時で、待ち時間後に接続先へ進みます。
- 同じ入力順とスケジューラー実行順なら、通知順も同じです。実時間の遅延は `setTimeout` に従い、ブラウザの負荷やバックグラウンド制限で遅れる場合があります。
- ループは遅延を含めて禁止します。未接続のブロックや空の作品は保存できます。
- `reset()` はカウンター、キュー、待機中の遅延を消去します。UI の描画や再生中の音を直接操作しません。
- `setGraph(next)` は新しいグラフを検証した後に `reset()` して置き換えます。不正なグラフなら置き換えず例外を返します。
- **UI の作品編集では、ブロックの移動や処理・出力の設定変更も `setGraph` の対象です。移動を確定すると、待機中の遅延とカウンターはリセットされます。** 座標だけの変更でも実行状態は引き継ぎません。
- `dispose()` は待機処理を消去してエンジンを終了します。以後の `trigger` と `setGraph` は例外になります。

リセットごとに世代番号を変えるため、キャンセルに失敗した古いタイマーが発火しても出力を流しません。遅延コールバックは一度だけ受理します。通知コールバックからのリセットやグラフ変更も、その場で古い伝播を止めます。

## 入力検証と実行上限

| 対象 | 上限・制約 |
| --- | --- |
| JSON ファイル | UTF-8 で 102,400 bytes |
| 作品 | ブロック 32 個、接続 64 本、作品名 120 文字 |
| ID | 英字始まり、英数字・`_`・`-`、48 文字以内 |
| 座標 | 有限数値、0〜3,000 |
| 遅延 | 整数 0〜10,000 ms、同時に 128 件まで |
| カウンター | 整数 1〜100 回 |
| しきい値 | 有限数値 −1,000,000〜1,000,000 |
| 音 | 有限数値 20〜20,000 Hz |
| 色 | `#RRGGBB` のみ |
| 実行作業 | 1 回の入力につき 2,048 ステップ、1 回のキュー処理も 2,048 ステップまで |

「ステップ」はブロック到着または遅延からの再開です。遅延をまたいだ分岐も、元の入力の上限を共有します。これは画面に通知される `node` / `edge` / `output` の合計数とは異なります。処理待ちキューも 2,048 件までです。

未対応のキー、種類、バージョン、重複 ID、重複接続、存在しない接続先、逆向きのポート接続、ループは拒否します。設定は既知の項目だけをコピーします。アクセサー、任意のプロトタイプ、`__proto__` などを作品へ持ち込めません。JSON 内の文字列をコードとして実行する機能はありません。

`trigger` が受け取れる値は有限の数値、真偽値、128 文字以内の文字列、`null` です。実行上限、タイマー開始失敗、通知側の例外では、待機処理を含めて実行をリセットし、`{ kind: 'error', message }` を通知します。その後は再び操作できます。

## 実機アダプターを追加する場合

**現バージョンに Bluetooth 接続や GATT の送受信処理はありません。** 将来の追加は、コアと UI から分離した任意のアダプターで行います。

```text
明示的な「機器を接続」操作
    ↓
任意アダプター ── 公開仕様に基づく受信・値の変換
    ↓
engine.trigger(対応する入力ブロックID, 正規化した値)
```

アダプターの責任は接続許可、公開仕様に基づく通信、対象機器と入力ブロックの対応付け、値の変換、切断時の購読解除です。接続の有無でシミュレーターの作品形式を変えません。既存入力を仮想操作と実機入力で共用する場合は、UI で入力元を明示します。

実機への出力を追加するなら、`output` の明示的な購読先として設計し、対応する公開コマンドと対象機器を限定します。保存ファイルを開いただけで機器へ命令を送る動作は追加しません。公開資料で分からない挙動は補完せず、未対応のまま残します。アダプターの完成条件には実機検証を別途設けます。

## テスト

```sh
node --test tests/core.test.cjs
```

Node.js 標準のテストランナーと仮想時計で、伝播順、しきい値、カウンター、遅延時刻、キャンセル、再入、入力検証、イベント過多を検証します。ここで検証するのは独自モデルです。ブラウザの音声・描画、実機や公式アプリとの挙動一致を証明するテストではありません。
