# フェーズと完了条件

## 選んだ形

**Patchlight — つないで、ひらめく。**

「実機を再現すること」より前に、「入力を出力へつなぐと、自分の仕組みになる」という理解を届ける独立教材を作る。初回は説明を読む前に端子を2回押し、ボタンを1回押せる構成にする。接続前には光らず、接続後に光るため、線をつなぐ意味を体験できる。

## Phase 0 — 公開範囲を確定〔実施済み〕

- 公式の製品・技術資料・SDK・MESH.js・LICENSE を確認。
- BLE/GATT の公開範囲、firmware 条件、7種類のブロック、SDK とアプリの違いを整理。
- 公式アプリ互換、独自プロトコル推測、ロゴや公式図版の流用を実装範囲に含めない。
- 成果: [PUBLIC-SPEC.md](PUBLIC-SPEC.md)、[TRADEMARKS.md](TRADEMARKS.md)。

## Phase 1 — 最初の30秒〔実装済み〕

- 空のエディターではなく、未接続のボタンとあかりから始まる。
- 「出力端子 → 入力端子 → 押す」の3操作で目に見える結果。
- ドラッグを必須にせず、クリック・タッチ・キーボードの同じ手順。
- アカウント、ネットワーク API、Bluetooth 許可、実機は不要。
- 見える操作ガイド、信号線の反応、点灯、イベント履歴。
- 完了確認: 自動ブラウザテストで初回経路を確認。**未説明の人間が30秒以内に理解するかは未測定**。公開後に人が確認する手順は後述。

## Phase 2 — 自分の仕組みに変える〔実装済み〕

- 入力4種類、処理3種類、出力3種類。全10種類。
- ブロックの追加・削除・移動・整列、配線の追加・削除、設定変更、命名、元に戻す・やり直す。
- 数値条件、待つ、数える、分岐・合流。独自の決定的なイベント規則。
- オリジナルの例: 暗さで点灯、来客音、2回振って色。
- 光・音・絵の出力シーン、絵の SVG 保存、色の選択、スマートフォンのブロック分類。
- JSON 保存/読み込み、端末への自動保存、URL フラグメント共有。
- 不正な入力の拒否、循環グラフ拒否、イベントとタイマーの上限、リセット時の取消。

## Phase 3 — 公開できる形に整える〔リリース準備を実装〕

- ライセンス、README、設計文書、一次情報、商標説明、貢献・セキュリティ案内。
- Node 単体テストと Chromium / Firefox / WebKit / モバイル幅のブラウザテスト。
- 静的ファイルの配布、サブディレクトリ対応、手動起動の GitHub Pages ワークフロー。
- 詳細な実行結果と未検証事項は [VALIDATION.md](VALIDATION.md)。
- 公開リポジトリ・Pages の実行記録は [VALIDATION.md](VALIDATION.md) に、ローカル検証と分けて記録する。

### 人による30秒確認

実機を持たず、説明を受けていない参加者5人に、新規ブラウザ状態の URL を渡す。ロード開始から点灯までを計測する。操作を教えない。

記録する項目:

1. 30秒以内に点灯したか。
2. 点灯後に「何をしたら、なぜ光ったか」を自分の言葉で説明できるか。
3. 止まった場所・見つからなかった操作。
4. 端末・ブラウザ・画面幅。

初期の合格基準は5人中4人以上が30秒以内に点灯し、入力と出力の関係を説明できること。結果が不足したら、先に初回ガイドと端子の見つけやすさを直す。自動テストの高速な操作時間を人間の理解時間として報告しない。

## Phase 4 — 所有者向けの実機入力〔任意・未実装〕

最初の対象は**ボタン1台からの入力だけ**。エディター・実行エンジンは共通のまま、接続アダプターから入力イベントへ変換する。

- BLE/GATT 公開仕様とライブラリを固定し、未知の値を推測しない。
- secure context / ユーザー操作 / ブラウザ選択ダイアログ / 対応ブラウザを確認。
- 接続拒否・取消・時間切れ・切断・再接続・電源断を実装してテスト。
- 実機型番・firmware・OS・ブラウザ版・操作と通知の対応を記録。
- モックだけで「実機対応」と表記しない。検証済み機能に限って互換性に言及する。
- LEDや他のセンサー、GPIO、複数台対応はそれぞれ別の実機検証後に追加。

初回のブラウザ体験にこのフェーズのコードや許可を読み込ませない。温湿度や GPIO の仮想教材も、利用者の具体的な題材が見えた段階で追加する。
